# 06.1 — IDEs Windows e integrações Ubuntu/MSYS2



## Política
VS Code e IntelliJ IDEA são **aplicativos gráficos instalados apenas no Windows**. Ubuntu WSL2 e MSYS2 não recebem pacotes completos dessas IDEs. Instalar servidores, extensões remotas ou scripts de lançamento para integração é permitido; isso não equivale a outra instalação da IDE.
## Dependências
Etapa 01 Windows/WinGet e PowerShell 7 → estrutura comum B → instalação WSL2 C e MSYS2 E → esta integração. IDEs podem ser instaladas antes do WSL, mas os testes remotos dependem da distribuição Linux já funcionar.
## 1. Windows: instalar IDEs pelo WinGet
```powershell
winget source update
winget install --id Microsoft.VisualStudioCode -e --accept-source-agreements --accept-package-agreements
winget search IntelliJ IDEA
```
Escolha explicitamente a edição do IntelliJ (Community/Ultimate ou distribuição atualmente disponível). Verifique ID e disponibilidade em `winget search`; instale com `winget install --id ID_CONFIRMADO -e`. Não presuma qual edição/licença o usuário tem. Se usar JetBrains Toolbox, escolha Toolbox como gerenciador, e não instale IntelliJ duas vezes.
Depois, feche e reabra os terminais:
```powershell
code --version
Get-Command code -ErrorAction SilentlyContinue
Get-ChildItem 'C:\Program Files\JetBrains' -ErrorAction SilentlyContinue
```
## 2. Windows: extensão oficial WSL do VS Code
```powershell
code --install-extension ms-vscode-remote.remote-wsl
code --list-extensions | Select-String 'remote-wsl'
```
Se `code` não estiver no PATH, procure o executável em `$env:LOCALAPPDATA\Programs\Microsoft VS Code\bin` ou reinstale habilitando integração ao PATH. O comando `code .` em uma distro WSL utiliza a interface Windows com o servidor remoto instalado automaticamente na distribuição para a extensão WSL; não instale pacote apt de VS Code dentro do Ubuntu.
## 3. Ubuntu WSL2: usar code .
```bash
sudo apt update
sudo apt install -y ca-certificates wget
command -v code || true
cd /workspace/projects/linux
code .
```
O comando `code .` deve abrir uma janela VS Code conectada à distribuição (indicador WSL). Na primeira vez, a extensão poderá instalar o componente VS Code Server naquela distro. Se `code` não existir, confirme instalação Windows, PATH da integração WSL, extensão e reinicie sessões; não substitua indiscriminadamente por `apt install code`.
## 4. Ubuntu WSL2: comando `idea .` sem instalar IntelliJ Linux
IntelliJ IDEA instalado no Windows abre diretórios WSL por `\\wsl.localhost\DISTRIBUICAO\workspace\projects\linux\PROJETO` e pode configurar SDK/JDK WSL. Esse comportamento não é o servidor remoto do VS Code; confira compatibilidade da edição e versão.
Localize o executável Windows `idea64.exe` pela instalação/JetBrains Toolbox. Ele será chamado pelo WSL interop usando o caminho Linux `/mnt/c/...`. **Não** use caminho Windows com barras invertidas como executável Bash.
No Ubuntu, crie o launcher (exemplo para abrir uma pasta; substitua o caminho exato da instalação):
```bash
mkdir -p /workspace/local/bin
cat > /workspace/local/bin/idea <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
: "${IDEA_WIN_EXE:?Defina IDEA_WIN_EXE como caminho /mnt/c/.../idea64.exe}"
target="${1:-.}"
[[ -e "$target" ]] || { echo "Arquivo ou pasta inexistente: $target" >&2; exit 2; }
target="$(realpath -- "$target")"
winpath="$(wslpath -w -- "$target")"
exec "$IDEA_WIN_EXE" "$winpath"
EOF
chmod 750 /workspace/local/bin/idea
```
Ajuste `IDEA_WIN_EXE` para o caminho real e persista-o no perfil Bash adequado, não no env de segredos:
```bash
export IDEA_WIN_EXE='/mnt/c/Program Files/JetBrains/NOME_INSTALACAO/bin/idea64.exe'
case ":$PATH:" in *:/workspace/local/bin:*) ;; *) export PATH="/workspace/local/bin:$PATH" ;; esac
cd /workspace/projects/linux/PROJETO
idea .
```
A primeira abertura deverá apontar para `\\wsl.localhost\...`, não copiar o projeto para NTFS. O wrapper básico suporta abrir uma pasta existente; amplie separadamente se quiser flags CLI e múltiplos arquivos. Se `idea64.exe` não iniciar pelo WSL, confira a opção WSL interop e a instalação Windows. Não instale IntelliJ Linux como atalho para resolver isso.
## 5. MSYS2 UCRT64: atalhos para Windows
```bash
command -v code || true
code /c/workspace/projects/windows
```
Para IntelliJ, crie alias/launcher no Home ou `/workspace/local/bin` do MSYS2 apontando para `idea64.exe` Windows; converta `$PWD` via `cygpath -w` antes de invocar .exe:
```bash
# Adapte o executável real
IDEA_EXE='/c/Program Files/JetBrains/NOME_DA_INSTALACAO/bin/idea64.exe'
"$IDEA_EXE" "$(cygpath -w "$PWD")"
```
Não compartilhe executáveis Linux com MSYS2 nem instale segunda IDE gráfica no MSYS2.
## 6. Verificação

- [ ] VS Code extensão WSL instalada no Windows

- [ ] WSL: `idea .` abre projeto WSL no IntelliJ Windows
