## 4. Instalação de dependências nativas Ubuntu
```bash
sudo apt install -y \
  git python3 python-is-python3 python3-venv python3-pip python3-dev pipx \
  curl wget ca-certificates unzip zip \
  build-essential cmake ninja-build
```
Git, Python e compiladores são nativos dessa distribuição; não utilize executáveis do Windows para builds Linux. Para Python, use ambientes virtuais em vez de instalar pacotes globais com pip.
### 4.1 Instalar SDKMAN e Java OpenJDK 21, Maven e Gradle
Instale **SDKMAN somente no Ubuntu WSL2**, depois de concluir a instalação dos pacotes `curl`, `zip` e `unzip` da etapa anterior. Não instale `openjdk-21-jdk`, Maven nem Gradle por apt em paralelo neste fluxo: o SDKMAN gerenciará as versões para evitar conflitos entre toolchains Linux.
Fonte oficial: [SDKMAN — instalação](https://sdkman.io/install/) e [guia de uso](https://sdkman.io/usage/).
```bash
# Inspecione a origem oficial antes de executar o instalador remoto
curl -fsSL https://get.sdkman.io -o /tmp/sdkman-install.sh
less /tmp/sdkman-install.sh
bash /tmp/sdkman-install.sh
source "$HOME/.sdkman/bin/sdkman-init.sh"
sdk version
```
O SDKMAN armazena SDKs na home da distro Linux por padrão (`~/.sdkman`), sem misturar com versões Windows. Para Java, escolha **uma versão disponível de JDK 21 OpenJDK/Temurin**, cujo identificador muda com atualizações:
```bash
sdk list java
# Substitua pelo identificador atual 21.0.12+1.1-tem exibido acima
sdk install java 21.0.12+1.1-tem
sdk default java 21.0.12+1.1-tem
sdk install maven
sdk install gradle
```
**Não execute literalmente ****`sdk install java VERSAO_21_TEM`**: é um marcador a substituir pela versão completa listada. A instalação padrão de Maven/Gradle usa versões estáveis disponíveis; projetos com versão fixa devem preferir `./mvnw` e `./gradlew`. SDKMAN também permite fixar versões por repositório usando `.sdkmanrc`, após decidir a política de versionamento.
Valide os executáveis nativos:
```bash
sdk current
java -version
javac -version
echo "$JAVA_HOME"
mvn -version
gradle --version
command -v java mvn gradle
```
Confirme Java 21 e caminhos Linux sob `~/.sdkman`. No novo shell, `sdk version` deve funcionar; caso contrário, confira a inicialização SDKMAN no perfil Bash (`~/.bashrc` ou equivalente). Não utilize `java.exe` do Windows como Java Linux.

## 6. Validação do ambiente
Execute **depois de instalar todas as dependências da seção 4, inclusive SDKMAN, Java 21, Maven e Gradle**, preferencialmente em uma nova aba Ubuntu do Windows Terminal. Não confunda os executáveis Linux com os do Windows.
### 6.1 Validar Ubuntu, Git, Python e compiladores
```bash
printf 'Usuario: '; whoami
uname -r
git --version
python3 --version
python --version
python3 -m pip --version
gcc --version | head -n 1
python3 -m venv /tmp/workspace-python-test
/tmp/workspace-python-test/bin/python --version
rm -rf -- /tmp/workspace-python-test
test -d /mnt/c && echo WINDOWS_MOUNT_OK
```
### 6.2 Validar SDKMAN e inicialização persistente
```bash
test -s "$HOME/.sdkman/bin/sdkman-init.sh" || { echo 'SDKMAN não instalado'; exit 1; }
source "$HOME/.sdkman/bin/sdkman-init.sh"
type sdk
sdk version
sdk current
```
`sdk` normalmente é uma função do shell, não um arquivo executável. A inicialização deve funcionar também em um **novo Bash interativo** sem executar `source` manualmente; se não funcionar, confira a configuração de inicialização em `~/.bashrc`.
### 6.3 Validar Java OpenJDK 21, JAVA_HOME, Maven e Gradle
```bash
java -version
javac -version
printf 'JAVA_HOME=%s\n' "$JAVA_HOME"
test -n "$JAVA_HOME" && test -x "$JAVA_HOME/bin/javac" && echo JAVA_HOME_OK

mvn -version
gradle --version

command -v java
command -v javac
command -v mvn
command -v gradle

readlink -f "$(command -v java)"
readlink -f "$(command -v mvn)"
readlink -f "$(command -v gradle)"
sdk current java
sdk current maven
sdk current gradle
```
**Resultado esperado:** `java -version` e `javac -version` retornam a linha 21; Maven e Gradle executam usando um JDK adequado; `JAVA_HOME` aponta para um JDK Linux válido. Normalmente os executáveis são links sob `~/.sdkman/candidates/{java,maven,gradle}/current/bin` e resolvem para versões instaladas pelo SDKMAN. Se algum comando apontar para `/mnt/c` ou para um `.exe` do Windows, corrija o PATH do Ubuntu antes de continuar. O Gradle Wrapper (`./gradlew`) e Maven Wrapper (`./mvnw`) devem ser preferidos quando existirem em um projeto.
