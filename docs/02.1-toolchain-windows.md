### 4.0 Git e Python
```powershell
winget install --id Git.Git -e --accept-package-agreements --accept-source-agreements
```

### 4.1 Instalar Java 21 OpenJDK pelo WinGet
Utilize **Eclipse Temurin 21**, distribuição OpenJDK LTS, como JDK do Windows. Maven e Gradle serão instalados separadamente por ZIP oficial, sem depender de pacotes ausentes no catálogo WinGet. O SDKMAN permanece exclusivo do Linux.
```powershell
winget search --id EclipseAdoptium.Temurin.21.JDK -e
winget install --id EclipseAdoptium.Temurin.21.JDK -e --accept-source-agreements --accept-package-agreements
```
Configure JAVA_HOME na seção 4.1.1 antes de instalar Maven e Gradle. Confirme `java -version` e `javac -version`, reabrindo o Windows Terminal se necessário.
### 4.1.1 Detectar JDK 21 do WinGet e configurar JAVA_HOME
Execute **antes de instalar ou validar Maven/Gradle**, em PowerShell 7. O pacote Eclipse Temurin pode ter instalado o JDK sem atualizar as variáveis da sessão já aberta. Este procedimento procura o JDK no registro de desinstalação (incluindo instalações por usuário) e nos diretórios padrão do Eclipse Adoptium; somente aceita uma pasta que contenha `bin\java.exe` e `bin\javac.exe`, verificando ser **Java 21**. Se houver mais de um JDK 21, mostra as opções e interrompe sem escolher silenciosamente.
```powershell
$roots = @(
  "$env:ProgramFiles\Eclipse Adoptium",
  "${env:ProgramFiles(x86)}\Eclipse Adoptium",
  "$env:LOCALAPPDATA\Programs\Eclipse Adoptium"
) | Where-Object { $_ -and (Test-Path -LiteralPath $_) }

$fromDisk = foreach ($root in $roots) {
  Get-ChildItem -LiteralPath $root -Directory -ErrorAction SilentlyContinue |
    Where-Object Name -Match '^jdk-21' |
    Select-Object -ExpandProperty FullName
}

$regKeys = @(
  'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*',
  'HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*',
  'HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*'
)
$fromRegistry = foreach ($key in $regKeys) {
  Get-ItemProperty $key -ErrorAction SilentlyContinue |
    Where-Object { $_.DisplayName -match 'Temurin.*21|Eclipse Adoptium.*21' } |
    ForEach-Object { $_.InstallLocation }
}

$candidates = @($fromDisk) + @($fromRegistry) | Where-Object { $_ } | ForEach-Object {
  [System.IO.Path]::GetFullPath($_).TrimEnd('\', '/')
} | Sort-Object -Unique
$valid = @($candidates | Where-Object {
  $_ -and
  (Test-Path -LiteralPath (Join-Path $_ 'bin\java.exe')) -and
  (Test-Path -LiteralPath (Join-Path $_ 'bin\javac.exe')) -and
  ((& (Join-Path $_ 'bin\javac.exe') -version 2>&1) -match 'javac 21(\.|$)')
} | Sort-Object -Unique)

if ($valid.Count -eq 0) {
  winget list --id EclipseAdoptium.Temurin.21.JDK -e
  throw 'Não encontrei JDK 21 Temurin. Verifique a instalação e o diretório do JDK.'
}
if ($valid.Count -gt 1) {
  $valid | ForEach-Object { Write-Host "JDK 21 localizado: $_" }
  throw 'Mais de um JDK 21 localizado. Selecione manualmente o diretório correto.'
}

$JdkHome = $valid[0]
[Environment]::SetEnvironmentVariable('JAVA_HOME', $JdkHome, 'User')
$env:JAVA_HOME = $JdkHome

# Inclua %JAVA_HOME%\bin no PATH de usuário, sem apagar entradas existentes.
$entry = '%JAVA_HOME%\bin'
$userPath = [Environment]::GetEnvironmentVariable('Path', 'User')
$parts = @($userPath -split ';' | Where-Object { $_ })
if ($parts -notcontains $entry) {
  [Environment]::SetEnvironmentVariable('Path', (($parts + $entry) -join ';'), 'User')
}

# Atualiza a sessão atual imediatamente.
$env:Path = "$JdkHome\bin;$env:Path"
Write-Host "JAVA_HOME = $env:JAVA_HOME"
& "$env:JAVA_HOME\bin\java.exe" -version
& "$env:JAVA_HOME\bin\javac.exe" -version
Get-Command java,javac | Select-Object Name,Source
```
**Observações:** se você já utiliza `JAVA_HOME` para outro projeto, avalie a substituição antes de executar. A alteração é no **usuário**, não em variáveis globais do computador, e não reinicia o Windows. Abra um terminal novo ao final e verifique `$env:JAVA_HOME`, `java -version`, `javac -version` e `mvn -version`. Quando houver conflito com o PATH de máquina, investigue `Get-Command java -All`.
### 4.1.2 Apache Maven por ZIP oficial (Windows): download, SHA-512, MAVEN_HOME e PATH
O catálogo WinGet desta instalação **não fornece ****`Apache.Maven`**. Instale Maven pela distribuição binária ZIP oficial; não dependa do WinGet. Fonte: [Apache Maven — Download](https://maven.apache.org/download.cgi) e [Apache Maven — Installation](https://maven.apache.org/install.html).
**Pré-requisito:** concluir `JAVA_HOME` e `java -version` com JDK 21 na seção 4.1.1. Execute com PowerShell 7 no contexto do próprio usuário. A versão abaixo é um exemplo disponível no site oficial; confirme a versão e os links na página de download antes de executar. Não confunda `-bin.zip` (distribuição executável) com `-src.zip` (código-fonte).
#### 1. Baixar e verificar SHA-512 antes de extrair
```powershell
$MavenVersion = '3.10.0'  # Conferir em https://maven.apache.org/download.cgi
$MavenBase = Join-Path $env:LOCALAPPDATA 'Programs\Maven'
$MavenFile = "apache-maven-$MavenVersion-bin.zip"
$MavenZip = Join-Path $env:TEMP $MavenFile
$MavenUrl = "https://dlcdn.apache.org/maven/maven-3/$MavenVersion/binaries/$MavenFile"
$MavenShaUrl = "$MavenUrl.sha512"

New-Item -ItemType Directory -Path $MavenBase -Force | Out-Null
Invoke-WebRequest -Uri $MavenUrl -OutFile $MavenZip -ErrorAction Stop
$MavenShaFile = Join-Path $env:TEMP "$MavenFile.sha512"
Invoke-WebRequest -Uri $MavenShaUrl -OutFile $MavenShaFile -ErrorAction Stop
$MavenChecksumText = (Get-Content -LiteralPath $MavenShaFile -Raw).Trim()
$ExpectedSha512 = ([regex]::Match($MavenChecksumText, '(?i)\b[0-9a-f]{128}\b')).Value
if (-not $ExpectedSha512) { throw 'Arquivo SHA-512 inválido; confira o link oficial.' }
$ActualSha512 = (Get-FileHash -LiteralPath $MavenZip -Algorithm SHA512).Hash
if ($ActualSha512 -ine $ExpectedSha512) { throw 'SHA-512 divergente; instalação interrompida.' }
Write-Host 'Integridade SHA-512 conferida.'
```
Nunca ignore verificação de hash. O SHA-512 protege a integridade contra corrupção; se o procedimento exigir autenticidade adicional, valide também a assinatura PGP indicada pela Apache.
#### 2. Extrair de forma idempotente e conferir o executável
```powershell
$MavenHome = Join-Path $MavenBase "apache-maven-$MavenVersion"
$MavenCmd = Join-Path $MavenHome 'bin\mvn.cmd'
if (Test-Path -LiteralPath $MavenCmd) {
    Write-Host "Maven $MavenVersion já instalado: $MavenHome"
} elseif (Test-Path -LiteralPath $MavenHome) {
    throw "Instalação parcial detectada: $MavenHome. Verifique antes de substituir."
} else {
    Expand-Archive -LiteralPath $MavenZip -DestinationPath $MavenBase
}
if (-not (Test-Path -LiteralPath $MavenCmd)) {
    throw "Maven não encontrado após extração: $MavenCmd"
}
& $MavenCmd -version
```
Não descompacte versões diferentes na mesma pasta. O diretório `$MavenBase\apache-maven-VERSAO` é exclusivo por versão, de modo análogo ao Gradle.
#### 3. Configurar MAVEN_HOME e PATH de usuário sem duplicações
O bloco não remove entradas preexistentes. Detecta tanto a entrada simbólica `%MAVEN_HOME%\bin` como o caminho físico, inclusive com barra final, antes de acrescentar a nova entrada. A sessão corrente também é atualizada somente quando necessário.
```powershell
if (-not (Test-Path -LiteralPath (Join-Path $MavenHome 'bin\mvn.cmd'))) {
    throw 'MAVEN_HOME inválido: bin\mvn.cmd não encontrado.'
}
$MavenHome = [IO.Path]::GetFullPath($MavenHome).TrimEnd('\','/')
if ([Environment]::GetEnvironmentVariable('MAVEN_HOME','User') -ne $MavenHome) {
    [Environment]::SetEnvironmentVariable('MAVEN_HOME', $MavenHome, 'User')
}
$env:MAVEN_HOME = $MavenHome
$MavenBin = Join-Path $MavenHome 'bin'
$SymbolicEntry = '%MAVEN_HOME%\bin'
$UserPath = [Environment]::GetEnvironmentVariable('Path','User')
$UserParts = @($UserPath -split ';' | Where-Object { $_ })
$HasEntry = @($UserParts | Where-Object {
    $entry = $_.Trim().TrimEnd('\','/')
    ($entry -ieq $SymbolicEntry) -or
    ([Environment]::ExpandEnvironmentVariables($entry).TrimEnd('\','/') -ieq $MavenBin)
}).Count -gt 0
if (-not $HasEntry) {
    [Environment]::SetEnvironmentVariable('Path', (($UserParts + $SymbolicEntry) -join ';'), 'User')
}
$SessionParts = @($env:Path -split ';' | Where-Object { $_ })
if (-not @($SessionParts | Where-Object {
    $_.Trim().TrimEnd('\','/') -ieq $MavenBin
}).Count) {
    $env:Path = "$MavenBin;$env:Path"
}
& (Join-Path $env:MAVEN_HOME 'bin\mvn.cmd') -version
```
A configuração de `MAVEN_HOME` não altera `JAVA_HOME` nem `GRADLE_HOME`. Caso o PATH já contenha uma versão antiga do Maven, investigue a precedência com `Get-Command mvn -All`; este procedimento evita adicionar repetidamente a entrada, mas **não remove automaticamente versões antigas**.
#### 4. Validação imediata do Maven
Neste ponto, valide apenas a instalação atual com `& (Join-Path $env:MAVEN_HOME 'bin\mvn.cmd') -version`. **Não abra ainda um novo terminal para o teste integrado de persistência:** primeiro conclua a instalação e configuração do Gradle na seção 4.1.3. Em projetos com `mvnw.cmd`, prefira o Maven Wrapper. Para atualizar o Maven, instale outro ZIP em pasta distinta e altere `MAVEN_HOME`.
### 4.1.3 Instalar Gradle pelo ZIP oficial (Windows)
**Não dependa do WinGet para Gradle neste ambiente.** Baixe a distribuição binária `gradle-VERSAO-bin.zip` da [página oficial de releases](https://gradle.org/releases/) e confira o SHA-256 disponibilizado pela Gradle. A [documentação oficial de instalação](https://gradle.org/install/) recomenda o ZIP *bin* para a maioria dos usuários.
**Primeiro**, conclua a configuração e validação de `JAVA_HOME` na seção 4.1.1 e confirme que Java 21 funciona: `java -version`. Execute no **PowerShell 7**. O exemplo usa uma versão explícita e um diretório de usuário, de modo que nenhuma pasta da workspace precise existir antes da instalação do WSL/MSYS2.
```powershell
$Version = '9.8.0' # Confira a versão desejada em https://gradle.org/releases/
$Base = Join-Path $env:LOCALAPPDATA 'Programs\Gradle'
$Zip = Join-Path $env:TEMP "gradle-$Version-bin.zip"
$Url = "https://services.gradle.org/distributions/gradle-$Version-bin.zip"
$ShaUrl = "$Url.sha256"

New-Item -ItemType Directory -Path $Base -Force | Out-Null
Invoke-WebRequest -Uri $Url -OutFile $Zip
$Expected = ((Invoke-WebRequest -Uri $ShaUrl).Content | Out-String).Trim()
$Actual = (Get-FileHash -LiteralPath $Zip -Algorithm SHA256).Hash
if ($Actual -ine $Expected) { throw "SHA-256 divergente: download NÃO confiável. Pare e confira a fonte." }

$Destination = Join-Path $Base "gradle-$Version"
if (Test-Path -LiteralPath $Destination) {
    Write-Host "Gradle $Version já extraído em $Destination; mantendo arquivos existentes."
} else {
    Expand-Archive -LiteralPath $Zip -DestinationPath $Base
}
$GradleBat = Join-Path $Destination 'bin\gradle.bat'
if (-not (Test-Path -LiteralPath $GradleBat)) {
    throw "Não foi encontrado gradle.bat: confira a estrutura extraída."
}
& $GradleBat --version
```
Se o hash falhar, **não prossiga** nem ignore a verificação. Não extraia outro ZIP por cima de uma versão já instalada. O diretório `$Base\gradle-VERSAO` permite manter várias versões lado a lado.
**Depois**, configure `GRADLE_HOME` e `PATH` de usuário sem apagar entradas preexistentes:
```powershell
[Environment]::SetEnvironmentVariable('GRADLE_HOME', $Destination, 'User')
$UserPath = [Environment]::GetEnvironmentVariable('Path', 'User')
$Entry = '%GRADLE_HOME%\bin'
$Entries = @($UserPath -split ';' | Where-Object { $_ })
if ($Entries -notcontains $Entry) {
    [Environment]::SetEnvironmentVariable('Path', (($Entries + $Entry) -join ';'), 'User')
}
$env:GRADLE_HOME = $Destination
$env:Path += ";$(Join-Path $Destination 'bin')"
gradle --version
```
Valide o Gradle na sessão atual com `gradle --version`. **Somente depois de configurar Java, Maven e Gradle, abra um novo Windows Terminal** para executar a validação integrada da seção 4.1.4. Certifique-se de que o Java reportado pelo Gradle seja o JDK correto. Se já houver outra instalação de Gradle em PATH, investigue a prioridade com `Get-Command gradle -All` antes de apagar entradas. Para atualizar Gradle, repita o download com uma nova versão validada e altere apenas `GRADLE_HOME` (o PATH não muda). Use `gradlew.bat` do repositório sempre que existir, pois o Wrapper controla a versão do projeto.
### 4.1.4 Validação integrada e persistência de JAVA_HOME, MAVEN_HOME e GRADLE_HOME
**Execute esta seção somente depois de finalizar as instalações e configurações das seções 4.1, 4.1.1, 4.1.2 e 4.1.3.** Feche todas as janelas abertas do Windows Terminal e abra uma **nova sessão PowerShell 7** para carregar as variáveis persistidas.
```powershell
$vars = 'JAVA_HOME','MAVEN_HOME','GRADLE_HOME'
foreach ($name in $vars) {
    $value = [Environment]::GetEnvironmentVariable($name,'User')
    $current = [Environment]::GetEnvironmentVariable($name,'Process')
    [pscustomobject]@{
        Variavel = $name
        Persistida = $value
        SessaoAtual = $current
        Valido = [bool]($value -and (Test-Path -LiteralPath $value))
    }
}

Get-Command java,javac,mvn,gradle -ErrorAction SilentlyContinue |
    Select-Object Name,Source
java -version
javac -version
mvn -version
gradle --version
```
Os três diretórios HOME devem existir e apontar para instalações Windows: JDK 21, raiz do Maven (`bin\mvn.cmd`) e raiz do Gradle (`bin\gradle.bat`). Confirme `JAVA_HOME` com `javac -version` (21); confirme a JVM utilizada nos relatórios de Maven e Gradle.
**Diagnóstico se funcionar apenas na sessão antiga:** compare as colunas Persistida/SessaoAtual, confirme o PATH de usuário e máquina com `[Environment]::GetEnvironmentVariable('Path','User')` e `'Machine'`, e inspecione `Get-Command java,mvn,gradle -All`. Se novas sessões herdarem o ambiente de um processo Windows Terminal antigo, feche todas as instâncias do aplicativo ou faça novo logon. Não reinstale as ferramentas nem duplique entradas no PATH para resolver uma sessão desatualizada.
O procedimento de instalação termina aqui. Prefira `mvnw.cmd` e `gradlew.bat` quando o repositório os fornecer, porque esses wrappers definem a versão da ferramenta para cada projeto.
### 4.2 Instalar Sysinternals Suite
Pacote Microsoft de administração e diagnóstico: Process Explorer, Process Monitor, Autoruns, TCPView, Handle, PsExec e outras ferramentas. O pacote contém utilitários avançados; algumas exigem elevação e aceitação da licença na primeira execução.
```powershell
winget search --id Microsoft.Sysinternals.Suite -e
winget install --id Microsoft.Sysinternals.Suite -e --accept-source-agreements --accept-package-agreements
winget list --id Microsoft.Sysinternals.Suite -e
```
**Atenção:** versões anteriores do manifesto da suíte já apresentaram falha de hash quando o arquivo ZIP oficial mudou. **Nunca desabilite verificação de hash ou integridade** para contornar. Se ocorrer, obtenha a suíte pela [página oficial da Microsoft](https://learn.microsoft.com/pt-br/sysinternals/downloads/sysinternals-suite), confira integridade e extraia em uma pasta apropriada de ferramentas Windows; registre a instalação. O pacote WinGet pode não adicionar todos os utilitários individualmente ao PATH. Valide o diretório instalado com `winget list` e localize `procexp64.exe`, `procmon64.exe` ou equivalentes na instalação, em vez de presumir que todos funcionarão pelo nome no terminal.
### 4.3 Instalar gsudo
`gsudo` permite solicitar elevação de **comandos Windows** a partir do PowerShell ou Terminal. Não substitui autorização administrativa, não concede permissões inexistentes e **não é o sudo Linux**.
```powershell
winget search --id gerardog.gsudo -e
winget install --id gerardog.gsudo -e --accept-source-agreements --accept-package-agreements
```
Feche e reabra os terminais para atualizar o PATH. Valide:
```powershell
Get-Command gsudo -ErrorAction SilentlyContinue
gsudo --version
gsudo whoami /groups
```
A última linha pode solicitar confirmação do Controle de Conta de Usuário (UAC). Use `gsudo` somente para comandos específicos que exigem elevação; evite trabalhar em um shell elevado permanentemente. Se precisar usar o gsudo dentro do MSYS2, configure a integração Bash separadamente após instalar o UCRT64.
### 4.4 Instalar Notepad++
Editor de texto Windows para arquivos PowerShell, Bash, YAML, JSON, Markdown, arquivos `.env` e scripts. Configurar codificação **UTF-8** e observar terminações de linha: PowerShell geralmente tolera CRLF, enquanto scripts Bash devem preferir **LF**.
```powershell
winget search --id Notepad++.Notepad++ -e
winget install --id Notepad++.Notepad++ -e --accept-source-agreements --accept-package-agreements
winget list --id Notepad++.Notepad++ -e
```
Abra o Notepad++ pelo menu Iniciar e confira **Configurações → Preferências** (idioma e comportamento de novos documentos). Ao editar scripts Linux/WSL, use **Editar → Conversão de final de linha → Unix (LF)** antes de salvar, quando necessário. Não abra arquivos com segredos apenas para copiá-los em locais sincronizados sem criptografia.
### 4.5 Instalar 7-Zip e WinRAR
**7-Zip** é a opção principal para compactação e extração em scripts Windows, com suporte a 7z, ZIP e diversos outros formatos. **WinRAR** é a opção complementar para trabalhar com arquivos RAR e recursos específicos do WinRAR; atenção às condições de licenciamento e eventual período de avaliação.
No PowerShell 7:
```powershell
winget search --id 7zip.7zip -e
winget search --id RARLab.WinRAR -e
winget install --id 7zip.7zip -e --accept-source-agreements --accept-package-agreements
winget install --id RARLab.WinRAR -e --accept-source-agreements --accept-package-agreements
```
Feche e reabra Windows Terminal e Explorer se a integração de menus ou o PATH ainda não refletir as instalações. Verifique os executáveis e versões:
```powershell
winget list --id 7zip.7zip -e
winget list --id RARLab.WinRAR -e
$SevenZip = Join-Path $env:ProgramFiles '7-Zip\7z.exe'
$WinRAR = Join-Path $env:ProgramFiles 'WinRAR\WinRAR.exe'
Test-Path $SevenZip
Test-Path $WinRAR
if (Test-Path $SevenZip) { & $SevenZip i | Select-Object -First 8 }
```
A localização indicada corresponde à instalação convencional em Program Files e pode variar. Para scripts multiplataforma, prefira descobrir o executável e não assumir que `7z` ou `rar` estejam no PATH. Não configure associações de arquivos sem necessidade.
### 4.6 Conferência dos pacotes de ferramentas
```powershell
winget list --id Microsoft.Sysinternals.Suite -e
winget list --id gerardog.gsudo -e
winget list --id Notepad++.Notepad++ -e
winget list --id 7zip.7zip -e
winget list --id RARLab.WinRAR -e
Get-Command gsudo -ErrorAction SilentlyContinue | Select-Object Source
```
Reabra o Windows Terminal após qualquer instalação que altere o PATH; reinicie Windows apenas quando o instalador ou recurso do sistema exigir.
